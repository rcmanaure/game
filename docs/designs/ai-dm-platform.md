## Vision

### Why this supersedes the prior plan
The prior plan was scoped for a free, static, text-only, Dark Pack-licensed
VTM fan game (explicit premise: no backend, no DB, no Docker). The user now
wants: an AI Dungeon Master that improvises (not fixed Tracery grammars),
generated monster/scenario art and simple animations (not text-only),
persistent user profiles, and eventual Steam distribution. Web research
confirmed neither Dark Pack (free, itch.io-only) nor Unbound (itch.io-
exclusive, 33% Paradox cut) permits Steam under the VTM IP — so the IP
itself had to change, not just the tech stack.

### 10x Check
Not just "an AI narrates dice rolls" (a commodity in 2026 — dozens of open-
source AI-DM projects already do this per research). The 10x version: a
world with real memory. Every completed chronicle writes NPCs, rivals, and
consequences back into a persistent store; those can resurface in future
runs (a blackmailer from run 3 shows up in run 7). Combined with a growing,
player-visible "bestiary" built from cached AI-generated monster art (cost
control turned into a collection mechanic), the game stops feeling like N
independent one-shots and starts feeling like one continuous world.

### Platonic Ideal
A player opens the game, is greeted by an AI DM whose narrative voice
already reflects their bloodline's flavor, sees an animated, illustrated
scene generated for their specific encounter (not a stock image), fights or
talks their way through it with dice resolved fairly by a separate logic
model (no rules hallucination), and at the end exports a shareable dossier
image. Their coterie's fate matters because permadeath is real, and the
world remembers what they did — for good or ill — the next time they play.

## CEO Review Hardening (11-section deep review, accepted fixes)

- **Mutation trust (Security):** logic-model JSON GameEvents pass a server-side
  rules validator (delta bounds per stat, legal state transitions) before
  being applied — schema-valid is not the same as rules-legal. Closes the
  prompt-injection-to-state-mutation gap (free-text player action shares a
  prompt with the model that emits state mutations).
- **Content-refusal handling (Error map):** LLM refusal/soft-refusal on
  violent or dark content is a first-class, expected failure mode for this
  genre, not a rare edge case. On detected refusal: retry with an alternate
  OpenRouter model with different content policy; if that also fails, fall
  back to a deterministic template for that specific event type. Never a
  silent no-op — that breaks the game roughly every third violent beat.
- **Spend cap / rate limit (Security):** Postgres-backed per-user/IP rate
  limit on DM turns (see Foundational Decision #9 — no Redis), plus a daily
  estimated-cost counter that gates DM access (not the rest of the app) if
  exceeded. Open registration + usage-billed OpenRouter (DM + image generation)
  without this is an unbounded-spend vulnerability.
- **Server-side turn idempotency (Data flow):** each turn gets a unique key
  before resolution; the mutation applies exactly once server-side
  (Postgres unique constraint on turn_id) even if the WebSocket drops
  mid-resolution and the client retries. Client-side button-disable alone
  (carried from the superseded plan) is insufficient now that permadeath
  and WebSocket streaming are both real — a double-applied damage event can
  kill a character that shouldn't have died, irreversibly.
- **Backups/rollback (Deployment):** daily `pg_dump` to storage separate
  from the VPS (not just Hostinger's weekly backup) PLUS continuous WAL
  archiving for point-in-time recovery (see Foundational Decision #12 —
  daily dump alone left up to 24h of permadeath loss exposed, which an
  outside-voice review caught as contradicting this plan's own promise),
  migrations tested in a local/staging container before applying to the
  VPS, documented step-by-step rollback procedure. Permadeath makes save
  corruption unrecoverable by design — higher stakes than a typical CRUD
  app.
- **Art-generation failure path (Error map):** encounters never block waiting on
  art generation. A generic per-archetype placeholder ships immediately;
  the real image generates in the background (OpenRouter image model,
  Decision #15) and replaces it via the existing WebSocket channel when
  ready.
- **Per-user scoping (Security):** every save/chronicle query resolves
  `user_id` from the JWT session, never from a request parameter — enforced
  as a reusable NestJS guard/decorator from the first endpoint, not
  retrofitted. Closes the IDOR surface that server-side profiles/saves open.
