## 1. Existing AI Dungeon Master / AI-narrated TTRPG projects

**Plan's "10x Check" claim ("AI narrates dice rolls" commodity in 2026) holds — but bigger find: why commodity version fails players, and it's not narration quality.**

### AI Dungeon (Latitude) — commodity narration, unmanaged context
AI Dungeon's own help center: memory failures architectural fact, not bug: "The AI can only look back so far in your adventure's history (called 'context' when it's passed into the AI model)" — roughly 4,000 tokens free users — and "when information starts falling out of context, the AI loses its ability to look back and reference certain parts of the story, meaning that most of the time, it's just making it up as best it can." Page's mitigations (Plot Essentials, "Memory System" manually re-injecting events, Retry/Edit) player-operated workarounds, not systemic fixes — page admits "not guaranteed to work 100% of the time."
Source: [AI Dungeon Help — Why does the AI forget or mix things up?](https://help.aidungeon.com/faq/why-does-the-ai-forget-or-mix-things-up)

### AI Roguelite (Steam) — sharpest evidence for plan's rules-layer bet
AI Roguelite closest existing shipped analog to this plan's shape: LLM-as-engine roguelite, stat/dice checks layered on free-text narration (own marketing: "plausibility assessment, stat checks with dice rolls based on your stats, and AI narrative generation"). But **no** deterministic, server-validated rules layer between LLM judgment and outcome — LLM itself decides plausibility, overrules numbers. Player feedback thread on game's own Steam forum documents exact failure mode Decision #7 (schema-validated GameEvents, rules-legal check before narration) designed to prevent: "swing a sword at an enemy with a lot of HP and they instantly die with one hit," a "leaf weapon" with higher stats than swords, NPC disposition drifting "regardless of player actions" because "rather than using stats and RNG for routine actions... the system consults the AI for everything, producing erratic results." Same thread flags unrecoverable world-memory drift: "world memory cannot be edited post-creation... NPCs continue referencing outdated objectives" after story state moved on.
Sources: [AI Roguelite on Steam](https://store.steampowered.com/app/1889620/AI_Roguelite/) · [Steam feedback thread](https://steamcommunity.com/app/1889620/discussions/0/4356744414622572721/) · [Steam discussion — memory extension trick](https://steamcommunity.com/app/1889620/discussions/0/599658601187078907/)

### Hidden Door — shipped product closest to plan's two-layer split
Hidden Door's FAQ: genuine hybrid architecture: "We update our game engine layer with a structured representation of everything in your world, from story events to character stats and conditions," enforced by "a dictionary of tens of thousands of words and phrases that are enriched with metadata that we use both for mechanical operations (you can't put a skyscraper into your inventory)." Story generation then "fractal combinatorial trope engine" — human-authored structured "beats" (recurring genre scenario, e.g. bar brawl) combined at runtime via programmatic logic, classical ML, LLMs, not pure free-text generation. Validates plan's Decision #6/#7 split (fixed taxonomy + rules validator, free narration within it) as real, working pattern in shipped product — not novel risk. FAQ doesn't explicitly describe cross-session/cross-playthrough persistent memory of kind plan's 10x Check claims (NPCs resurfacing later runs); persistence scoped to within given world/story.
Source: [Hidden Door FAQ](https://www.hiddendoor.co/help/faq)

### Open-source landscape — checking plan's "dozens" claim directly
Plan's own text asserts "dozens of open-source AI-DM projects already do this." GitHub search for `"AI dungeon master"` repos plus `ai-dungeon-master`, `dungeon-master`, `solo-rpg` topic pages turns up at least dozen independent repos matching description across two search passes (`nickwalton/AI-DungeonMaster`, 79 stars; `Sagesheep/NarrativeEngine-P`, 77 stars; `electronistu/Project_Infinity`, 41 stars; `deckofdmthings/GameMasterAI`, 35 stars; plus `djnightmare9909/Dungeon-master-OS-WFGY`, `eeshsaxena/ai-dungeon-master`, `benjcooley/dungeongod-agi`, `shawnrushefsky/dmcp`, `ITMO-Agentic-AI/ai-dungeon-master`, `samvoisin/ai-dungeon-master`, `ell-hosse/AI-Dungeon-Master`, `fedefreak92/dungeon-master-ai-project`, `tegridydev/dnd-llm-game`) — "dozens" holds order-of-magnitude, though every one small hobby project (max 79 stars, none Steam presence or meaningful install base), which plan's text doesn't currently qualify.
Sources: [GitHub search — "AI dungeon master" repositories](https://github.com/search?q=%22AI+dungeon+master%22&type=repositories&s=stars&o=desc) · [GitHub topic — ai-dungeon-master](https://github.com/topics/ai-dungeon-master) · [GitHub topic — solo-rpg](https://github.com/topics/solo-rpg)

Highest-starred, most feature-complete repo found — `Sagesheep/NarrativeEngine-P` — most direct open-source analog to plan's two-layer split, own README useful primary source for both halves of 10x Check claim. Rules layer: ships "Dice Fairness system" that "pre-rolls d20 pools each turn and injects structured outcomes for 7 skill categories... ensuring the GM uses real rolls rather than fabricating outcomes" — genuinely deterministic layer separate from LLM, distinct mechanism from plan's schema-validated GameEvent approach (pre-rolled pools vs server-side rules validation of LLM-emitted mutations) but proof "deterministic layer distinct from LLM judgment" not unclaimed territory in open source either. Memory: README claims deep *within-campaign* recall ("the GM can accurately recall that Bob betrayed the party in Chapter 3... even if that was 50 chapters and 200 sessions ago") but no claim of persistence *across separate, completed playthroughs* — memory scoped to one continuous campaign, however long.
Source: [GitHub — Sagesheep/NarrativeEngine-P README](https://github.com/Sagesheep/NarrativeEngine-P)

### Verdict on the 10x Check claim
"AI narrates dice rolls" confirmed commodity — AI Dungeon (2019), AI Roguelite (2022), open-source landscape (dozens repos, one highly-featured) all already ship it. What's genuinely rarer per evidence above: (a) rules layer specifically validating LLM-emitted state *mutations* against legality/bounds server-side before applying (AI Roguelite no such layer, hence "instant one-hit kills"; NarrativeEngine-P's pre-rolled dice pools different narrower mechanism; Hidden Door comparable engine layer but closed commercial platform, not visible open prior art), and (b) persistent memory surviving single continuous campaign becoming memory *across separate completed playthroughs* — no product surveyed here, commercial or open-source, does that; every memory system found (AI Dungeon's context window, NarrativeEngine-P's full-transcript recall, Hidden Door's engine layer) scoped to one ongoing story. Stronger, more specific support for plan's differentiator than plan's own text currently states — plan frames Decision #7's rules-validator as risk-mitigation hardening against prompt-injection, when market evidence above says robust version of same layer also competitive point of difference in own right. (Framing observation about Vision/10x Check section's own language, not persistent-memory or bestiary mechanic, so not repeated as numbered item in Candidate plan amendments below, scoped to those two mechanics specifically.)

## 2. Persistent-world / roguelike-legacy mechanics

Common thread every example below: **memory lands through surfacing and attribution at specific, named touchpoint — not through existence of database.** Fact stored but never re-surfaced to player invisible; games that "feel like world remembers you" all have dedicated screen, character, or moment whose entire job hands past-run facts back to player, tied to proper noun.

### Rogue Legacy (Cellar Door Games) — death becomes named heir, not game-over
Cellar Door Games' own official product page, fetched directly: "Each time you die, your child will succeed you. Every child is unique. One child might be colorblind, another might be a dwarf with vertigo. But that's OK, because no one is perfect, and you don't have to be to succeed." Per secondary GDC-postmortem coverage (session recording not directly transcribed here), system evolved specifically to soften permadeath's harshness — "player deaths lead to new heirs inheriting gold, upgrades, and randomized traits, allowing gradual advancement without full resets," evolving from early idea of plain leaderboard into full genealogical lineage screen. Mechanic that matters: player sees specific successor with specific quirks, not reset counter.
Sources: [Cellar Door Games — Rogue Legacy (official page, fetched directly)](https://www.cellardoorgames.com/roguelegacy) · [GDC Vault — Rogue Legacy Design Postmortem: Budget Development](https://www.gdcvault.com/play/1020541/Rogue-Legacy-Design-Postmortem-Budget)

### Darkest Dungeon (Red Hook Studios) — named heroes carry consequence forward within a run
Red Hook's own stated design goal: "We wanted to capture the human response to stress. Any person can break under pressure, and people break in different ways" — deliberately not Call of Cthulhu's "insanity" filter: "we never really thought of things in the strict 'insanity' filter that many Call of Cthulhu games adopt." Mechanic (Stress → Affliction check → named, persistent quirk like paranoia or masochism attached to specific recruited hero) same "surface it on proper noun" pattern: game's memory of hero's trauma legible as trait on that hero's character sheet, not hidden variable.
Source: [Game Developer — Game Design Deep Dive: Darkest Dungeon's Affliction System](https://www.gamedeveloper.com/design/game-design-deep-dive-i-darkest-dungeon-s-i-affliction-system)

### Dwarf Fortress (Bay 12 Games) — browsable ledger of consequence, seeded and comparable
Tarn Adams' stated goal: "fantasy world generator" where "the things that you did before will impact the future and so forth." Confirmed by directly fetching Game Developer feature (not search snippet), Adams describes exactly how seed determinism makes consequence legible: "you could run one world out to 110 years, say, and the same world out to 100 and play the last ten years yourself instead. You'd end up with two 110-year worlds with near identical histories, but the last ten would diverge... Legends mode lets you compare what has happened, to random people or locations or whatever. Somebody that might have lived out their life peacefully in the non-player 110-year world might have been conscripted to die in one of your saw traps in the year 105 in the player-influenced world." On what gets recorded: "The players can impact all of it pretty much, and it keeps track of what they do in Legends mode, the same as worldgen." Mechanic that makes this land for player (not just design intention): **Legends mode** itself — browsable in-game history viewer, same underlying data structures as world generation. Lesson: *comparable, browsable* record (not just "stuff happened somewhere in a DB") makes consequence feel real.
Source: [Game Developer — How Tarn Adams upgraded and optimized Dwarf Fortress for its official Steam release (fetched directly, quotes confirmed)](https://www.gamedeveloper.com/programming/how-tarn-adams-upgraded-and-optimized-dwarf-fortress-for-its-official-steam-release) · [Dwarf Fortress Wiki — Legends](https://dwarffortresswiki.org/index.php/DF2014:Legends)

### Hades (Supergiant Games) — repetition reframed as continuity, not reset
Greg Kasavin (Supergiant) on why repeated deaths read as narrative progress instead of erased progress: characters directly acknowledge loop — "It's a rematch now, and you've learned a little bit more and you're maybe a little bit stronger too" — game's own fiction (player character immortal god) supplies diegetic justification: "you're an immortal god with no sense of the passage of time... you could just infinitely play the game... and just keep having these unique experiences." Per secondary coverage of separate Kasavin forum comment (not in GeekDad interview fetched above, not independently verified here vs primary source), also mechanically enforced via *relationship state* gating which of several pre-written variants of a scene plays — distinct dialogue branches keyed to relationship level with specific character (e.g. Megaera). Relevant for coterie-sim regardless of that one unverified detail: GeekDad-confirmed material above already establishes characters acknowledging specific returning player, tied to named NPC, is load-bearing mechanic — relationship/history with specific recurring NPC, not just "world state," is what returning player notices.
Source: [GeekDad — Narrative and Early Access: Supergiant's Greg Kasavin Discusses Hades Development](https://geekdad.com/2019/10/narrative-and-early-access-supergiants-greg-kasavin-discusses-hades-development/)

### Death Stranding (Kojima Productions) — asynchronous traces of specific past action
Kojima on Social Strand System: "you can see the tracks and traces, so you can feel or think about the other people," and on "likes" mechanic — deliberately not currency or power-up — "unconditional love," designed to make players ask "what would people think if I put it here?" before leaving structure behind. **Explicit constraint from task brief applies here:** this plan's scope single-player, community-almanac idea already deferred indefinitely (Scope Decision #5 in design doc), so transferable lesson *not* "add other players' traces" — it's Death Stranding's underlying mechanic of **attributing world-state change to specific, later-surfaced past action**, applied to player's *own* prior playthroughs rather than social graph.
Source: [Game Informer — Hideo Kojima Answers Our Questions About Death Stranding](https://gameinformer.com/interview/2019/09/16/hideo-kojima-answers-our-questions-about-death-stranding)

## 3. Collection / bestiary mechanics

### Monster Hunter — progressive entry completion on single cached asset (directly reusable pattern)
*(Sourced from community-documented fan guides, not Capcom developer statement — numbers below player-measured, not official design docs, but mechanic itself directly observable in shipped game.)* Monster Hunter's Hunter's Notes ties bestiary completeness to numeric **research level** per monster (4-6 tiers depending on title), earned by repeated field activity: "Collecting tracks adds about 10 research points, killing a monster adds about 60, and capturing adds about 90." Each research level unlocks *more information about same monster entry* — "weak spots, severable/breakable parts, elemental and status weaknesses, and a list of potential materials" — not new asset. Closest existing precedent for plan's Decision #6 constraint (art keyed to small fixed archetype enum, not free text): Monster Hunter proves *closed, finite* bestiary can still deliver collection-progression feel without new art per entry — depth of single cached entry the lever, not breadth of entries.
Source: [Attack of the Fanboy — What Do Research Points Do in Monster Hunter: World?](https://attackofthefanboy.com/guides/monster-hunter-world-guide-research/) · [GamerGuides — Monster Ph.D. Trophy Guide](https://www.gamerguides.com/monster-hunter-world/guide/walkthrough/trophy-guide/monster-ph-d)

### Pokédex — completion as primary long-tail hook, entries locked to direct encounter
*(Sourced from Bulbapedia, fan-maintained wiki, and TechRadar report of Junichi Masuda statement rather than original interview — cited as best available secondary account, not primary Game Freak doc.)* Documentation of Pokédex confirms base mechanic: "detailed entries are not recorded until the player obtains the Pokémon," gating full completion behind direct capture (not just sighting), with formal in-fiction completion reward ("diploma" from Game Freak's in-universe director). Notably, Game Freak's producer reported to have stated retreat from *ever-growing* Pokédex scope ("we now have no plans to make the Pokémon that are missing in the Galar Pokédex in-game available") — signal unbounded, always-growing collection target has own scope-management cost, data point favoring plan's already-fixed archetype taxonomy over open-ended one.
Source: [Bulbapedia — Pokédex](https://bulbapedia.bulbagarden.net/wiki/Pok%C3%A9dex) · [TechRadar — Pokémon Sword and Shield's Pokédex cut could be permanent](https://www.techradar.com/news/pokemon-sword-and-shields-pokedex-cut-could-be-permanent)

### Slay the Spire / Slay the Spire 2 (Mega Crit) — unlocks as lore delivery, with documented failure mode to avoid
*(The "unlocking cards is awkward" complaint below from player suggestion thread on game's own Steam hub, not Mega Crit statement — cited as real, observed player friction, not developer intent.)* Original Slay the Spire ties card/relic unlocks to per-character run progress. Player thread on Steam Community forum documents directly relevant risk: "unlocking cards is awkward, as it can make your runs more difficult the more you unlock, often making consistent decks harder to build" — i.e., collection-unlock mechanic interfering with core gameplay loop it's bolted onto is real, reported failure mode, not hypothetical. Per third-party coverage, Slay the Spire 2 responds by tying unlocks ("Epochs") explicitly to lore delivery ("each Epoch representing a major lore drop about the Spire's history") rather than pure power unlocks — closer to this plan's bestiary concept (codex/lore reward, not power-progression system), signal lore-flavored unlocks sidestep balance trap pure-power unlocks fell into.
Source: [Steam Community — player thread, "Improvements to the meta progression system"](https://steamcommunity.com/app/646570/discussions/2/1696043263503477251/) · [GamerBlurb — Slay the Spire 2 Progression Guide](https://gamerblurb.com/articles/slay-the-spire-2-progression-guide)

## 4. Dark-fantasy / vampire-adjacent original IP differentiation

### Fallen London / Sunless Sea (Failbetter Games) — differentiation through invented vocabulary, not mechanics
*(Sourced from Hardcore Gaming 101, independent games-history site, and Failbetter's own game-description page — not developer design-process interview; no such interview found this pass.)* Failbetter's "Neath"/"Zee" setting differentiates almost entirely through dense, original in-fiction vocabulary and prose style rather than novel systems — "the style of the writing... makes heavy use of alliteration, obtuse language, and dense wordplay," with specific named "Terror Meter" (not generic "sanity" or "fear" stat) that "measures your exposure to darkness and madness" with dedicated flavor text and visual stings at thresholds. Lesson for this plan: distinctive *name* for mechanic, consistently used in flavor text, does more differentiation work than underlying number itself, functionally fear/sanity meter like many other games'.
Source: [Failbetter Games — Sunless Sea](https://www.failbettergames.com/games/sunless-sea) · [Hardcore Gaming 101 — Sunless Sea](https://hg101.kontek.net/fallenlondon/sunlesssea.htm)

### Bloodborne (FromSoftware) — coined stat name (Insight) carries both lore and mechanical weight
*(Sourced from TheGamer, secondary games-guide site — no direct FromSoftware design statement on Insight name found this pass; observation about mechanic's function verifiable from shipped game itself.)* Insight simultaneously resource, lore concept, and difficulty lever (raising it changes enemy behavior, unlocks NPC dialogue/vendors), deliberately never explained directly in-game — "Bloodborne never goes out of its way to explain Insight's many uses," consistent with FromSoft's environmental-storytelling-over-exposition house style. Distinct from this plan's stat naming (see below), Insight zero shared vocabulary with any prior licensed IP — reads native to Bloodborne specifically.
Source: [TheGamer — Bloodborne: A Complete Guide To Insight](https://www.thegamer.com/bloodborne-insight-complete-guide/)

### Darkest Dungeon (Red Hook Studios) — see Section 2 above
Same source as Section 2: Red Hook explicitly rejected reusing "insanity" mechanics/terminology from genre's own obvious precedent (Call of Cthulhu) favoring original terms ("Stress," "Affliction," "Virtue") grounded in psychology rather than cosmic horror. Most directly on-point precedent for game visibly gothic/horror-adjacent but wanting distinct branding from most obvious genre forebear.

### A finding worth flagging back to the plan (not resolved here)
Foundational Decision #1 in `docs/designs/ai-dm-platform.md` states project drops "official VTM IP/Dark Pack license," Implementation Notes state "no VTM branding, no VTM canon terms, anywhere." Checking that claim vs plan's own IP-naming line ("bloodlines, Hunger, Humanity, Veil-of-secrecy") vs V5 (Vampire: The Masquerade 5th Edition, current White Wolf/Paradox edition) surfaces two findings of different strength, not one:
- **"Hunger"** V5's specific, signature dice-pool mechanic name (resource literally driving V5's core dice-rolling system) — distinctive, load-bearing term unique to that edition, not generic English word used incidentally. Stronger flag.
- **"Humanity"** also literal V5 stat name, but much more generic term in wide use across dark-fantasy/horror genre outside White Wolf (a "how human do you still feel" stat exists, under same plain-English name, in other vampire/horror games too) — weaker, lower-confidence flag than "Hunger."
Every successful differentiation case researched above (Sunless Sea's "Terror," Darkest Dungeon's "Stress"/"Affliction," Bloodborne's "Insight") achieves distinctiveness specifically by *not* reusing precedent genre's own term for near-identical mechanic — "bloodlines" (vs "clans") and "Veil-of-secrecy" (vs "Masquerade") already follow that pattern in this plan; "Hunger" currently doesn't, "Humanity" arguably doesn't either though less clearly. Factual observation about internal consistency with Decision #1's own stated rule, not legal opinion — flagged here neutrally, two terms kept separate rather than presented as equally strong, for future `/plan-ceo-review` pass to resolve.

## Candidate plan amendments

Scoped tightly to two mechanics named in this research request — persistent-world-memory and bestiary — not general punch list. (Two other findings surfaced during research, Hunger/Humanity naming gap and rules-validator-as-differentiator framing, recorded where they belong in Sections 1 and 4 above rather than repeated here, since neither is persistent-memory or bestiary mechanic.) Each amendment below fits inside existing Foundational Decisions — no new service (consistent with Decision #9's no-Redis stance: Postgres rows + prompt slot + UI surface only), no free-text art keys (would break Decision #6's cache economics), no multiplayer/social layer (Scope Decision #5's community-almanac deferral stays deferred). Candidates for future `/plan-ceo-review` pass, not decisions.

1. **Progressive bestiary entries, Monster Hunter-style, on existing fixed archetype cache.**
   Add per-user, per-archetype "familiarity level" counter (encounters survived/defeated with that archetype) stored as Postgres row. Gate *how much of cached art/lore card shown* on that counter (e.g. silhouette-only → full card → card + monster-specific tactical note) rather than generating new art per tier. Cost: one integer column + one UI conditional; zero new art-gen calls, since reveals more of *same* cached asset per Decision #6's archetype cache rather than requesting new ones. Directly resolves tension between Decision #6's need for small closed archetype set (cache economics) and collection mechanics' usual need for breadth to feel like "collecting" — progressive-reveal on small set sidesteps trade-off entirely (Monster Hunter precedent, Section 3).

2. **A named "returning face" surfaced at chronicle start, not just a queryable NPC table.**
   Persistent-world memory (Scope Decision #4, post-v1) risks becoming invisible database if only queryable, per Section 2 finding memory lands through *dedicated surfacing touchpoint*, not storage existing. Concretely: at start of new chronicle, if prior playthrough recorded NPC player meaningfully interacted with (blackmailer, rival, spared enemy), DM's opening narration beat deterministically references that specific named NPC by name/fact before any dice rolled — one-node addition to existing LangGraph StateGraph (a `recall` node before `resolve`, querying existing Postgres NPC/consequence table by user_id) plus prompt-injection slot for creative model. No new storage beyond what post-v1 persistent memory already requires — presentation-order change, not new data model.

3. **A single-player "chronicle ledger" screen (Dwarf Fortress Legends-mode-lite), not a stats page.**
   Post-v1 persistent memory currently has no stated player-facing surface beyond "NPCs can resurface." Add minimal, plain-list, per-account page (query against same NPC/consequence table from #2, no new writes) showing past chronicles' key outcomes in order — "Chronicle 3: spared the blackmailer / Chronicle 5: coterie fell to Final Death." Cheapest possible version of Dwarf Fortress's browsable-history lesson (Section 2): point isn't rich viewer, it's that player can *look up* what world remembers instead of only encountering it by surprise. Read-only query + list template; no new schema.
